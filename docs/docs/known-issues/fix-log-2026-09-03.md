# Fix log — 2026-09-03

## CI smoke rules used obsolete destinations

- **Symptom:** The CI smoke script reported failures after the date-first routing change, even though the rule engine generated the intended destinations.
- **Root cause:** `tools/smoke_rules.py` still expected the pre-date-first folder layout and exited successfully despite failed expectations.
- **Change:** Updated expectations to the current date-first layout, corrected vacation-name matching for underscore-delimited filenames, and made failed expectations return a non-zero exit code.
- **Regression risk:** The smoke script now correctly blocks CI when routing changes break its documented contract.

## macOS smoke path construction was not portable

- **Symptom:** The macOS runner failed before expectation checks with a `Path.relative_to` error.
- **Root cause:** The synthetic root used a hardcoded Windows path (`C:/...`), which `pathlib` treated as a relative component on macOS.
- **Change:** The smoke script now creates its root with `tempfile.mkdtemp()` and `pathlib.Path`, so every runner uses a native absolute path.
- **Regression risk:** Temporary smoke roots are left to the operating system's temporary-directory cleanup policy.

## Temporary path aliases broke relative-path reporting

- **Symptom:** Windows and macOS CI failed in `Path.relative_to` even with a temporary root.
- **Root cause:** The OS exposed equivalent temporary paths under different aliases (Windows short names and macOS `/private` symlink resolution).
- **Change:** Resolve both the temporary root and each generated destination before calculating relative paths.
- **Regression risk:** None; this affects only smoke-report formatting, not file operations.
