# Fix log — 2026-09-02

## `FilePicker` registered on `page.services`, not `page.overlay`

- **Symptom.** With Flet 0.86.5, the folder-picker button click produced a red "Unknown control: FilePicker" block in the window, and every `await picker.get_directory_path(...)` call timed out after 10 seconds with `RuntimeError: Timeout waiting for invoke method listener for FilePicker(N).get_directory_path`.
- **Root cause.** In Flet 0.80+ the `Service` base class moved into a separate registry on the page. Adding a `Service` subclass (such as `FilePicker`) to `page.overlay` still runs without raising, but the client never wires up the invoke-method listener, so calls time out and the service renders as an unknown stub.
- **Fix.** Register the picker on `page.services`, not `page.overlay`. See `src/tidyra/presentation/app.py` for the wiring:

  ```python
  picker = ft.FilePicker()
  page.services.append(picker)   # correct in Flet 0.86+
  app.picker = picker
  ```

- **Regression risk.** Low. `page.overlay.append(...)` is the broken pattern; the regression test is "does `get_directory_path` return within 10 seconds?".
- **Codified in.** `docs/docs/frontend/invariants/frontend.md` §5. Treat the rule as load-bearing — do not "modernise" it back to `overlay` without an ADR.

## Nested scroll removed on Preview and Results screens

- **Symptom.** On the Preview and Results screens, the outer `Column` had its own `scroll` enabled. Wheel events were captured by the page-level scroll instead of the plan/result list, so the inner list's scrollbar never moved.
- **Root cause.** Two competing scroll containers. Wheel events route to the topmost scrollable control; with both active, the inner list silently lost the scroll.
- **Fix.** Removed `scroll` from the outer `Column` on Preview and Results. The list card keeps `expand=True` so it fills the available vertical space; the outer container no ` scroll.
- **Regression risk.** Low. If the screen grows taller than the window on small monitors, prefer making the list card smaller, not re-adding an outer scroll.
- **Codified in.** The pattern is in `src/tidyra/presentation/views/preview.py` and `results.py`. The lesson is captured informally here so future contributors know why the outer scroll is missing on purpose.

## `Image.fit` takes `ft.BoxFit`, not `ft.ImageFit`

- **Symptom.** On first launch after adding the brand mark to the home view header, Flet surfaced a red banner: `Error running app — module 'flet' has no attribute 'ImageFit'`. The window title rendered (so `page.window.icon` was already wired), but the home view never finished painting.
- **Root cause.** On Flet 0.86.5, `ft.Image(...).fit` is typed `Optional[BoxFit]`. The old `ft.ImageFit` enum does not exist on this module surface. The error message ("no attribute 'ImageFit'") is misleading — it suggests the symbol is missing, but the real issue is that the name was renamed to `BoxFit` somewhere between Flet 0.27 and 0.86.
- **Fix.** Use `ft.BoxFit.CONTAIN` (or any other `BoxFit` value) wherever the older code expected `ft.ImageFit.X`. For the brand row the equivalent is just dropping `fit=` — the SVG's viewBox + the explicit `width`/`height` already constrain the raster, but `BoxFit.CONTAIN` is the safest default for any future reused image.
- **Regression risk.** Low. The change is a one-line constant rename in the home view header; `BoxFit.CONTAIN` matches `ImageFit.CONTAIN` semantically. `ruff check` and `mypy` both pass after the rename.
- **Codified in.** The brand-row code in `src/tidyra/presentation/views/home.py` and the example snippet in `docs/docs/frontend/invariants/frontend.md`.

## OS window icon kept showing the Flet logo despite `page.window.icon`

- **Symptom.** After wiring `page.window.icon = str(logo_path())` (where `logo_path` resolves to `tidyra-logo.svg`), the home view rendered correctly but the OS title bar still showed Flet's pink "F" logo next to the "Tidyra" window title.
- **Root cause.** Flet 0.86's `Window.icon` field documents itself as "The file should have the `.ico` extension … Has effect on Windows only" (verbatim from `flet/controls/core/window.py`). SVG paths are silently ignored — the OS title bar falls back to the Flet engine binary's own icon. The in-app brand mark worked because `ft.Image(...)` renders the SVG directly; the OS decoration never did.
- **Fix.**
  1. Added `tools/build_icon.py` — a stdlib-only ICO generator (zlib + struct, no Pillow) that renders the brand mark into a 32x32 RGBA buffer, encodes it as PNG, and wraps it in an ICO container.
  2. Generated `src/tidyra/resources/tidyra-icon.ico` (151 bytes, valid ICONDIR/ICONDIRENTRY headers, PNG payload, all CRCs verified).
  3. Added `presentation.brand.icon_path()` for the ICO alongside `logo_path()` for the SVG; updated `app.py:main` to set `page.window.icon = str(icon_path())`.
  4. Packaged `*.ico` alongside `*.toml` / `*.svg` via the hatch artifacts glob in `pyproject.toml`.
- **Verification.** Rendered pixel buffer: folder body sampled at (8, 9) = `(15, 118, 110, 255)` (`#0F766E` deep teal); file card at (16, 16) = `(94, 234, 212, 255)` (`#5EEAD4` light teal); corners = `(0, 0, 0, 0)` (fully transparent). ICO header parsed: `type=1`, `count=1`, `bpp=32`, `offset=22`, PNG signature present.
- **Regression risk.** Low. The change adds a new resource and helper. If the user's screenshot still shows the Flet icon after this commit, the most likely cause is that the OS cached the old icon — restart Explorer (`Stop-Process -Name explorer -Force`) or sign out to clear.
- **Codified in.** `docs/docs/frontend/invariants/frontend.md` §4 ("Window icon is the `.ico`, not the SVG"); `docs/docs/frontend/index.md` brand-assets table.
