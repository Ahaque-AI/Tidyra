# Tidyra — Initial Scaffold Plan

**Date:** 2026-09-02
**Branch:** main
**Status:** Approved
**Spec:** `docs/superpowers/specs/2026-09-02--tidyra-design.md`

## Goal

Scaffold the Tidyra project end-to-end so that `uv run tidyra` opens the Flet desktop app, the user can pick a folder, scan it, see a preview, and organize files safely — without any automated tests in this release.

## Order of execution

Steps are sequential. Each one is small, leaves the project in a working state, and is verified before moving on.

### Step 01 — Project bootstrap

**What:** Create `pyproject.toml`, `.gitignore`, `uv.lock`, package skeleton.
**Why:** Lock the runtime (uv + Python 3.11+), tooling (ruff, mypy), dependencies (flet, platformdirs), and entry point before any code lands.
**Files:**
- `pyproject.toml`
- `.gitignore`
- `uv.lock` (generated by `uv sync`)
- `src/tidyra/__init__.py` (empty package marker)
- `src/tidyra/__main__.py` (so `uv run tidyra` works as a module too)

**Verification:** `uv sync` succeeds; `uv run python -c "import tidyra"` imports cleanly.

**Depends on:** none.

---

### Step 02 — Domain layer

**What:** `FileEntry`, `OrganizationRule`, `SkipReason`, `FileOperation`, `OrganizationPlan`, `OrganizationStrategy`, `PlanValidator`, `RuleBasedStrategy`.
**Why:** Pure domain — no Flet, no I/O. The shape everything else depends on.
**Files:**
- `src/tidyra/domain/__init__.py`
- `src/tidyra/domain/models.py`
- `src/tidyra/domain/rules.py`
- `src/tidyra/domain/plans.py`
- `src/tidyra/domain/strategies.py`

**Verification:** `uv run python -c "from tidyra.domain.plans import OrganizationPlan"` succeeds; mypy strict passes on `src/tidyra/domain/`.

**Depends on:** Step 01.

---

### Step 03 — Filesystem abstraction

**What:** `FileSystem` Protocol + `LocalFileSystem` (pathlib-based).
**Why:** The only layer that touches the real filesystem. Validator + executor consume it.
**Files:**
- `src/tidyra/infrastructure/__init__.py`
- `src/tidyra/infrastructure/filesystem.py`

**Verification:** `uv run python -c "from tidyra.infrastructure.filesystem import LocalFileSystem"` succeeds.

**Depends on:** Step 02.

---

### Step 04 — Configuration loader + default rules

**What:** `ConfigService` that loads TOML with user-dir → CWD → built-in-defaults precedence. Ship the built-in defaults.
**Why:** Decouple TOML from domain. Provide a working out-of-the-box experience.
**Files:**
- `src/tidyra/infrastructure/configuration.py`
- `src/tidyra/resources/default_rules.toml`

**Verification:** `uv run python -c "from tidyra.application.services import ConfigService; ConfigService().load()"` returns ≥7 rules; default TOML parses without error.

**Depends on:** Steps 02, 03.

---

### Step 05 — Application services

**What:** `Scanner`, `OrganizeService`. The orchestration layer that wires scanning → strategy → validation → executor.
**Why:** Presentation talks only to application. Domain stays pure.
**Files:**
- `src/tidyra/application/__init__.py`
- `src/tidyra/application/scanner.py`
- `src/tidyra/application/services.py`
- `src/tidyra/application/organize.py`

**Verification:** `uv run python -c "from tidyra.application.organize import OrganizeService"` succeeds; manual sanity run on a tempdir (no automated test).

**Depends on:** Steps 02–04.

---

### Step 06 — Flet presentation

**What:** App shell + state + three views (home, preview, results) + four components (folder picker, file list, plan view, result view). Handlers call `OrganizeService` and update `UIState` only.
**Why:** Thin UI. The whole reason the architecture exists.
**Files:**
- `src/tidyra/presentation/__init__.py`
- `src/tidyra/presentation/state.py`
- `src/tidyra/presentation/app.py` (entry point)
- `src/tidyra/presentation/views/__init__.py`
- `src/tidyra/presentation/views/home.py`
- `src/tidyra/presentation/views/preview.py`
- `src/tidyra/presentation/views/results.py`
- `src/tidyra/presentation/components/__init__.py`
- `src/tidyra/presentation/components/folder_picker.py`
- `src/tidyra/presentation/components/file_list.py`
- `src/tidyra/presentation/components/plan_view.py`
- `src/tidyra/presentation/components/result_view.py`

**Verification:** `uv run tidyra` opens the Flet window; user can pick a folder; scan produces a preview; organize button is disabled until a valid plan exists.

**Depends on:** Step 05.

---

### Step 07 — Documentation

**What:** README, CONTRIBUTING, CHANGELOG, and the four `docs/` files. README follows the public-GitHub template in the spec.
**Why:** Open-source quality bar.
**Files:**
- `README.md`
- `CONTRIBUTING.md`
- `CHANGELOG.md`
- `docs/architecture.md`
- `docs/configuration.md`
- `docs/development.md`
- `docs/roadmap.md`

**Verification:** Each doc opens without obvious placeholders. README mentions `uv sync` / `uv run tidyra` only — no `pip`, no manual venv instructions.

**Depends on:** none (can be done in parallel with steps 02–06).

---

### Step 08 — End-to-end verification

**What:** Run the full check suite and smoke-launch the app.
**Why:** Definition of Done, item 16.
**Commands:**
```powershell
uv sync
uv run ruff check .
uv run ruff format --check .
uv run mypy src
uv run tidyra
```

**Verification:** ruff exits 0, ruff format exits 0, mypy exits 0, Flet window opens.

**Depends on:** Steps 01–07.

---

## Out of scope (this release)

- Automated tests (pytest removed per user decision).
- `LLMStrategy` implementation (interface only).
- Undo / history.
- Custom rule editor UI.
- Background scheduling.

## Open assumptions

- Python 3.11+ available on the dev machine (tomllib is stdlib).
- Flet 0.28+ available on PyPI.
- The dev machine has uv installed (the spec defers uv installation to the official docs if not).
